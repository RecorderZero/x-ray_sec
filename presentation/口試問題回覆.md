## Q1. 一張影像的處理時間？一個反演或生成階段多久？

**結論**：部署操作點（DPM++ N=100）下，**單一反演或單一生成階段約 1.8 秒/張**；完整「匿名化＋還原」4-pass 來回**約 6.3 秒/張**；相較學長原版（dense DDIM T=500）的 ~30.8 秒/張，快約 **4.9×**。

**[事實] 單一階段（one pass＝一次反演 或 一次生成）時間**（`assets/W9-T1_sampler_comparison.csv`，4 圖平均）：

| 步數 N | DPM++ 單階段秒數 | 相對 full-density 加速 |
|---|---:|---:|
| 499（同算力對照） | 9.10 | 1× |
| 200 | 3.67 | 2.5× |
| **100（部署點）** | **1.80** | 5× |
| 50 | 0.90 | 10× |
| 25 | 0.46 | 20× |

- 一次「匿名化」＝反演＋加密＋生成匿名圖＋存檔 ≈ 2 個階段；一次「還原」＝反演匿名圖＋解密＋生成還原圖 ≈ 2 個階段。整條 4-pass 來回因此 ≈ 4×單階段。
- **[事實] 整條 4-pass 端到端時間**（`assets/comparison.csv`，含存檔）：ours N=100 ≈ **6.3 s/張**；學長原版 ≈ **30.8 s/張**。
- **[事實] 階段是對稱的**：forward（反演）與 backward（生成）每步各一次 model 呼叫，時間幾乎相同（W9-T1 中 ddim/dpm pass 秒數同量級）。偽健康圖若用 CFG（gs≠0）每步需 2 次 model 呼叫，時間加倍，另計。
- **[事實] 正式 RQ4 主表（security_v1 N=200，patient-cluster CI）已完成**（`paper_assets/rq4_formal/`）：完整 4-pass runtime P **6.15 s/張**[CI 6.150, 6.154]、S2fn **6.31 s/張**[6.306, 6.310]（單 GPU、batch=1；batch 化可再攤銷）。還原保真見 Q9。

## Q2. 有沒有測試這個架構是否會產生幻覺（hallucination）？

**結論**：有**間接**證據顯示還原圖**未系統性產生幻覺病灶**，但我們**尚未做專門的「幻覺量化指標」**；且已誠實記錄在少數病例觀察到局部紋理幻覺。

**正面證據（間接、已量測）**：
- **[事實] 高頻不無中生有**：HF-fidelity（`assets/W9-T7_hf_fidelity.csv`）Laplacian 變異比 = **0.896（<1）**，代表還原圖的高頻能量**略低於**原圖、並未額外長出高頻結構；RAPSD 高頻帶 retention 0.964、HP-SSIM 0.988。若有幻覺（憑空加細節），高頻會**超過**原圖。
- **[事實] 病理不被竄改**：獨立第三方分類器（torchxrayvision，零重訓，`assets/W9-T8_referee_pathology.csv`）在 11 病理上 recovered AUC ≈ real（macro Δ ≤ 0.003）。若還原**捏造或抹除**病灶，裁判的 rec 相對 real 會系統性偏移；實測沒有。

**誠實界線**：
- **[限制][觀察]** 在少數 P（恆等金鑰）還原圖中，可見原圖沒有的**細小「字樣狀」紋理**（`assets/AF017_P_anonymization_smoke.png`、`assets/E2.5_roundtrip_grid.png`），屬生成模型的**局部幻覺**，**尚未量化**。
- **[限制]** 上述都是影像端 proxy 與 ML 裁判，**非放射科醫師判讀**；我們沒有專做「幻覺率」這種指標。若口委要求，可補一個「還原圖相對原圖的新增高頻結構 / 假陽性病灶」量表，但目前的設計機制上已移除最可能致幻的因素：還原改為**無條件（null）**，不再把還原預偏向「健康」類（見 Q8 與 supersede AF-018/021）。

## Q3. 如何抵禦模型反轉攻擊？模型反轉攻擊是什麼？

**模型反轉攻擊（Model Inversion Attack）是什麼**：攻擊者利用模型的輸出、參數、梯度或中間表徵，**反推還原出私密的輸入資料**（這裡即病患原始 X 光片）。在本架構的威脅模型裡，最相關的是 **T2-WB**：攻擊者拿到**公開的匿名影像＋目標擴散模型/程式/sampler**（Kerckhoffs 假設：模型公開，只有 master key 保密），嘗試反演回原圖或還原金鑰。

**我們如何抵禦**（來源：`paper_assets/threat_model_attack_map.md`）：
1. **[設計] 公開的只有「密文影像」**：發布出去的匿名圖是 noise-like 密文，還原需要授權金鑰。沒有金鑰者，對它做任何 inversion 得到的仍是密文 latent。
2. **[事實] 學習式再識別打不穿**：部署忠實 MC-2（shadow-1000 learned Siamese 攻擊發布像素圖）victim AUC = **0.430 ≈ 隨機**；外部 Packhäuser re-id top-1 = **0.05 = 隨機**。對照組（未加密還原圖）victim AUC 0.635 → 證明攻擊**有能力**、是**加密**把它擋掉。
3. **[事實] per-image nonce 阻斷「一把金鑰通吃」**：學長原版是全域固定金鑰且金鑰與影像無關，`table_A4.6`（`assets/table_A4.6_reconstruct.csv`）顯示攻擊者只需 **8 對（原圖,匿名圖）**就能還原金鑰、把受害者原圖**逐位元重建**（attacker-vs-legit PSNR=100、SSIM=1.0）。我們的 S2 改成 **per-image nonce**，金鑰映射**無法跨影像轉移**（見 Q6 cross-nonce cos≈0.001），竊得一張的資訊不能套到別張。

**[限制]** 這是**指定攻擊的實測**（固定統計、學習式 Siamese、frozen encoder），非通用安全證明；但涵蓋了「模型反轉」在本威脅模型下最強的具體形式。

## Q4. Key space 多大？真的夠安全嗎？

**結論**：我們的 S2 用 **256-bit CSPRNG 主金鑰**（＋每張 128-bit nonce），遠大於學長的有效 32/64 bits。**但「金鑰空間大」本身不是我們的安全論證** —— 真正的防線是 per-image nonce 與密文不變量被破壞（見 Q3/Q6）。

**[事實] 學長原版（我們攻破的 baseline，`assets/table_keyspace.csv`）**：

| 方案 | 宣稱 | 實際有效金鑰上界 | 已知一對明密文的工作量 |
|---|---|---:|---:|
| S0 Rademacher | 2^d（d=65536） | **32 bits** | **0（直接讀出）** |
| S1 Signed-Perm | 2^d · d! | **64 bits**（password 模式） | **0（排序即得）** |

→ 學長宣稱天文數字金鑰空間，實際由一個 32-bit SHA-256 前綴 seed 決定；且持一對明密文時金鑰直接讀出，不需搜尋（唯密文也 ≈2^32 單張即可破）。

**[設計] 我們的 S2**（`src/crypto/kdf.py`）：
- 主金鑰 = **均勻隨機 256-bit**（`MASTER_KEY_BYTES=32`，CSPRNG，不接受整數 seed），經 **HKDF 域分離**展開到各子金鑰（SOT 用 ChaCha20、AEAD 用 ChaCha20-Poly1305、外層 HMAC-SHA256）。
- 每張影像 **128-bit nonce**（`NONCE_BYTES=16`）。

**[限制／誠實重點]** 依本專案規範（skill §8），**不以金鑰空間當安全性論證**：
- 金鑰空間大 ≠ 安全。學長的反例正是「宣稱 2^d 卻 32 bits、且 KPA 下為 0」。
- S2 的安全來自：(a) **per-image nonce** 使跨影像映射不可轉移、(b) 加密**破壞**了 abs/sorted-abs/norm/geometry 這些再識別不變量、(c) AEAD/HMAC 的完整性。256-bit 只是把「暴力搜金鑰」這條路堵死到不可行，是**必要但非充分**。

## Q5. 金鑰如何管理？以人為主還是以 X 光片為主？醫生離職怎麼辦？誰能存取 X 光片與金鑰？

**結論**：**金鑰與影像綁定（以 X 光片為主的 per-image nonce），但主金鑰由機構保管（以機構為主，非個別醫師）**。「醫生離職 / 存取權」屬**部署營運政策**，我們提供了支撐它的密碼學機制，但完整的機構金鑰治理是**部署層／未來工作**，不在本論文的密碼學貢獻內。

**[設計] 已實作的機制**（`src/crypto/`）：
- **一把機構 master key（256-bit）**，經 **HKDF 域分離**對每張影像、每個用途導出子金鑰；主金鑰本身不直接參與加密、不落在影像裡。
- **每張影像一個 128-bit nonce**，寫入 **nonce registry**（`nonce.py`：SQLite `UNIQUE(scope,nonce)`，跨行程原子檢查，**拒絕重用**）。還原所需的真實 norm、M1 lo/hi 等 metadata 用 **ChaCha20-Poly1305 AEAD 容器**加密保存（`s2_fixed_norm.py`、`container.py`）。
- 因此「誰能還原 X 光片」= 誰持有 master key；發布出去的匿名圖對無金鑰者是密文。

**[限制] 屬部署營運、非本論文量化範圍**：
- **以人 vs 以片**：加密是 per-image（以片），但**解密權限**取決於 master key 的保管模型。建議採「機構金鑰託管 + 角色存取控制（RBAC）」而非把金鑰發給個別醫師。
- **醫生離職**：對應 **key rotation / 存取撤銷**——因為是機構託管、per-image nonce，撤銷某人的存取不需要重新加密所有影像，只需撤銷其對 master key/HSM 的存取。這套金鑰生命週期（HSM、輪替、稽核日誌）是標準 KMS 實務，**我們的架構相容但未實作與量測**。
- **誰能存取**：發布影像（密文）＝任何拿到檔案者皆可見但讀不出病理；原圖還原＝僅 master key 持有者（機構授權角色）。這條界線在論文中可明確陳述為部署假設。

## Q6. 能否防 CCA / CPA / KPA？金鑰是否每次不一樣、是否會重複？

**結論**：**KPA/CPA 的跨影像轉移被 per-image nonce 阻斷；主動竄改（近似 CCA 面向）被 AEAD/HMAC 擋下；金鑰每張不同、實測不重複。** 但這是**指定攻擊的實測**，非形式化 IND-CCA 證明。

**[事實] 金鑰每張不同、不重複**（`assets/table_repeat.csv`，同明文重複加密 100 次）：
- 100/100 **nonce 全唯一**、100/100 **payload 全唯一**；密文兩兩 off-diagonal cosine 平均 **3.7e-5**（≈ 不相關）。→ per-image nonce 確保不重複。

**[事實] KPA / CPA（`assets/table_cross_nonce.csv`）**：
- **同 nonce**（正控制，證明攻擊實作正確）：full-map KPA/CPA **可完整還原**映射（max_abs≈2.4e-15、cos=1.0）。
- **跨 nonce**（實際部署情形）：**失效**（cos≈**0.0011**、rmse≈1.41）。→ 持有某張的完整明密文，**無法**解另一張。

**[事實] 主動竄改 / CCA 面向（`assets/table_tamper.csv`）**：
- S2 對 tag/nonce/ciphertext/version/parameters/aad/storage **7 種竄改全部拒絕（7/7）**；對照 S2a（無 MAC）接受竄改 → 證明 HMAC 的必要性。學長原版無完整性檢查，30/30 竄改全被接受。

**[限制／誠實重點]（skill §8）**：
- 正交旋轉**本身不解決 KPA**（同金鑰下仍可由明密文解出映射）；**真正阻止跨影像的是 per-image nonce**，不是旋轉也不是金鑰空間。
- 我們做的是**指定攻擊（KPA/CPA/tamper）的實測 + 正控制**，**不**宣稱形式化 IND-CPA/IND-CCA 安全。

## Q7. 兩篇原始論文對病灶定位的討論與數據？目前學術進展？我們有無相關數據、狀況如何？

**[事實] 學長論文**（`past/Privacy-Preserving...Lesion Localization...pdf`）：
- 定位是其標題與主打，但**以差異圖定性呈現**：「透過 reconstructed image 與 pseudo-healthy image 的 pixel-wise difference map 來 accurately highlight/localize pleural effusion」——**未報自己的 Dice/IoU**。文中引用的 Dice 0.96%→5.55% 是**別人的 DP baseline 弱點**（當作動機），非學長成績。

## Q8. S2 保持 norm 有沒有讓 latent 維持高斯分布？還是其實不用管高斯？

**結論**：**固定 norm 的目的是封住「L2-norm 再識別旁道」（AF-025），不是為了「維持高斯」。** 正交 SOT 本來就同時保留高斯形狀與 norm；高斯性**既非我們的安全論證、也非必要條件**。

**[事實] 分布診斷（D6.3，`assets/D6.3_gaussian_distribution.png`）**：對 N(0,1) 合成向量做 SOT 變換，前後做 KS 檢定與 Normal Q-Q —— SOT 是**正交變換**，把高斯旋轉後**仍是高斯**（直方圖與 Q-Q 幾乎重合）。所以「加密會不會破壞高斯」答案是：正交變換**不會**。

**[事實] 固定 norm 的真正理由**（`src/crypto/s2_fixed_norm.py`，`FIXED_NORM=248.261`）：
- S2 v1（純正交）**必然保留 L2 norm** → norm 本身變成一個**跨影像不變量**，可被 norm-linkage 再識別攻擊利用（threat map §2.3：T2-WB range-preserving 下 norm Top-1=0.25，顯著）。
- v2 把每張 latent 先縮放到**公開固定 norm C**、真實 norm 以 AEAD 私密保存 → 這個旁道被壓回隨機（Top-1=0.005），且保真代價 ≈ 0（§4e：S2fn ≈ S2a）。

**[結論／誠實重點]**：
- 「維持高斯」**不是**安全的充要條件，**不該**拿來當安全論證（skill §8）。安全來自 per-image nonce + 不變量被破壞。
- 固定 norm 之後，latent 落在**半徑固定的球面**上（不再是嚴格 N(0,I) 的 χ-norm 分布），但在 d=65536 高維下高斯 norm 本就極度集中於 √d≈256 附近，固定到 C=248.26 只移除了極小的 norm 散度；**每座標邊際仍 ~高斯**，解碼（decode 回影像）行為正常。所以「維持高斯」對**解碼管線正常運作**有幫助，對**安全**則由 nonce 負責——兩者分開講。

## Q9. FID 是什麼？我們需要量嗎？

**FID（Fréchet Inception Distance）是什麼**：用 Inception 網路的特徵，比較「生成影像集合」與「真實影像集合」兩個分布的 Fréchet 距離，是**生成模型的分布真實度**指標（越低越像真實分布）。它衡量的是**一群生成圖整體像不像真實 X 光**，不是逐張對原圖的保真。

**結論：我們不需要把 FID 當主指標。**
- **[事實]** 我們的任務是**可逆匿名化**，不是無條件生成。還原圖的品質是**逐張、對原圖的配對保真**，已用 **PSNR / SSIM / cosine / L∞ / LPIPS** 量。FID 是**無配對的分布距離**，用在這裡資訊量低且會誤導。
- **[事實] 正式 RQ4 主表（N=200、部署 DPM++ N=100 null、patient-cluster CI，`paper_assets/rq4_formal/`）**：還原保真 **P 45.74 dB [45.60, 45.88]**、**S2fn 46.42 dB [46.19, 46.63]**；SSIM 0.992/0.995、cosine 0.99996、**LPIPS 0.029/0.019**（感知近乎無損）。匿名圖對原圖單輪 PSNR S2fn **僅 5.27 dB**（noise-like 密文，隱私正常）。對照凍結 legacy 操作點（Q8_FORMAL）P 37.46 dB → 部署點 **+8.3 dB**。這些配對指標已充分涵蓋「還原品質」，FID 非必要。
- **[事實]** 匿名圖是 **noise-like 密文**（設計如此），對它算 FID 無意義（它本就不該像真實 X 光）。
- 學長的程式（`evaluation_metrics.py`）確實有算 FID，但那是沿用生成模型慣例；對「可逆性/隱私」的主張無幫助。
- **[建議]** 若口委堅持要一個「還原圖整體是否仍落在真實 X 光分布」的佐證，可**選配**在**還原圖**上報 FID（對原圖集合），但它與 LPIPS/SSIM 的結論高度重疊、屬 nice-to-have；**匿名圖不量 FID**。
